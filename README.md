# 무드튠 (MoodTune)

기분 키워드(설렘, 위로, 새벽감성 등)를 고르면 **내 [Navidrome](https://www.navidrome.org/) 서버에 있는 곡** 중에서 어울리는 곡을 골라 주고, 바로 재생해 주는 웹 앱입니다.

- 곡 목록, 재생, 즐겨찾기는 모두 Navidrome 서버에서 가져옵니다. (OpenSubsonic API 사용)
- Navidrome은 곡의 분위기 수치를 주지 않으므로, **장르를 기분에 대응시키는 표**(`js/engine.js`)로 추천합니다. 표의 숫자는 추정치이니 내 라이브러리에 맞게 고쳐 쓰세요.
- 별도 빌드나 설치 없이 HTML/CSS/JS만으로 동작합니다.

## 파일 구성

```
index.html                  화면
css/style.css               스타일
js/engine.js                장르 → 기분 표, 점수 계산 (가장 자주 고치게 될 파일)
js/subsonic.js              Navidrome(Subsonic API) 클라이언트
js/md5.js                   토큰 인증용 MD5
js/app.js                   화면 동작
js/demo.js                  서버 없이 둘러보기용 샘플 곡
server/proxy.js             화면 + Navidrome 프록시 서버 (Node.js, 패키지 설치 불필요)
test/                       테스트와 모의 Navidrome 서버
.github/workflows/pages.yml GitHub Pages 자동 배포
```

## 방법 A. 프록시 서버로 실행

### 1) 먼저 모의 서버로 연습하기 (선택)

Navidrome이 아직 없거나, 앱이 잘 도는지 먼저 보고 싶을 때 쓰는 가짜 서버입니다.

PowerShell 창 **하나**에서:

```
node test/mock-navidrome.js
```

- **하는 일:** 가짜 Navidrome을 `http://127.0.0.1:4533`에 띄웁니다. 샘플 34곡과 8초짜리 사인파 소리가 나옵니다.
- **성공:** `모의 Navidrome 실행 중: http://127.0.0.1:4533 (사용자 demo / 비밀번호 sesame)`
- 이 창은 **켜 둔 채로** 두세요. 끄려면 `Ctrl + C`.

**새 PowerShell 창**을 같은 폴더에서 열고:

```
$env:NAVIDROME_URL="http://127.0.0.1:4533"
node server/proxy.js
```

- **첫 줄이 하는 일:** 이 창에서만 쓰는 설정값 `NAVIDROME_URL`에 연결할 서버 주소를 넣습니다. 창을 닫으면 사라집니다.
- **둘째 줄이 하는 일:** 무드튠 화면을 열어 주고, Navidrome으로 가는 요청을 대신 전달하는 서버를 시작합니다.
- **성공:**
  ```
  무드튠이 실행됐습니다.
    브라우저에서 열기:  http://127.0.0.1:8080
    Navidrome 서버:     http://127.0.0.1:4533
    종료하려면 Ctrl + C
  ```
- 브라우저에서 `http://127.0.0.1:8080`을 열고, 설정 탭에서 서버 주소는 그대로(`/navidrome`) 두고 사용자 `demo`, 비밀번호 `sesame`로 연결합니다.

### 2) 내 Navidrome 서버에 연결하기

위 모의 서버 단계는 건너뛰고, PowerShell에서:

```
$env:NAVIDROME_URL="http://192.168.0.10:4533"
node server/proxy.js
```

`192.168.0.10:4533`은 예시입니다. 평소 Navidrome 웹 화면에 접속하는 주소를 그대로 넣으세요. 맨 끝에 `/`는 붙이지 않습니다.

| 화면에 나온 메시지 | 뜻과 해결 |
|---|---|
| `[오류] NAVIDROME_URL 환경 변수가 필요합니다.` | 첫 줄(`$env:...`)을 빠뜨렸습니다. 같은 창에서 두 줄을 차례로 실행하세요. |
| `[오류] NAVIDROME_URL 형식이 올바르지 않습니다` | 주소가 `http://` 또는 `https://`로 시작하지 않습니다. |
| `[오류] 포트 8080를 이미 다른 프로그램이 쓰고 있습니다.` | `$env:PORT="8081"`을 먼저 실행하고 다시 시작하세요. 주소도 `:8081`로 바뀝니다. |
| `[오류] Navidrome에 연결하지 못했습니다 (ECONNREFUSED)` | 해당 주소에서 Navidrome이 꺼져 있거나 주소·포트가 틀렸습니다. 브라우저로 그 주소가 열리는지 먼저 확인하세요. |
| `... (CERT_HAS_EXPIRED)` 또는 `(DEPTH_ZERO_SELF_SIGNED_CERT)` | 서버의 HTTPS 인증서 문제입니다. 자체 서명 인증서라면 `$env:NAVIDROME_INSECURE="1"`을 추가로 실행하세요. |

**macOS / Linux**는 한 줄로 실행합니다: `NAVIDROME_URL=http://192.168.0.10:4533 node server/proxy.js`

**폰에서도 쓰고 싶다면** (같은 와이파이): `$env:HOST="0.0.0.0"`을 추가로 실행하고 시작한 뒤, 폰 브라우저에서 `http://<이 컴퓨터의 IP>:8080`으로 접속합니다. 이 경우 같은 네트워크의 누구나 접속할 수 있으니 공용 와이파이에서는 쓰지 마세요.

## 방법 B. GitHub Pages로 배포

### 1) GitHub에 저장소 만들기

1. https://github.com/new 에서 저장소 이름(예: `moodtune`)을 입력합니다.
2. 아래의 "Add a README", ".gitignore", "license" 체크는 **모두 끈 채로** 만듭니다. 이 프로젝트에 이미 파일이 있어서, 체크하면 첫 업로드가 충돌합니다.
3. GitHub Pages는 무료 계정에서는 **Public 저장소**일 때 사용할 수 있습니다. 요금제에 따라 달라질 수 있으니 GitHub 문서에서 확인하세요.

### 2) 이 폴더를 GitHub에 올리기

이 프로젝트 폴더에서 PowerShell을 열고 **한 줄씩** 실행합니다. (Git이 없으면 https://git-scm.com 에서 설치)

```
git init
```
- **하는 일:** 이 폴더를 Git 저장소로 만듭니다.
- **성공:** `Initialized empty Git repository in ...`

```
git add .
```
- **하는 일:** 올릴 파일을 모두 목록에 담습니다. 아무 메시지가 없으면 정상입니다.

```
git commit -m "무드튠 첫 버전"
```
- **하는 일:** 지금 상태를 하나의 기록으로 저장합니다.
- **성공:** `... files changed, ... insertions(+)`
- **실패:** `Please tell me who you are`가 나오면 아래 두 줄을 먼저 실행하고 다시 시도합니다.
  ```
  git config --global user.name "내 이름"
  git config --global user.email "github에 등록한 이메일"
  ```

```
git branch -M main
```
- **하는 일:** 기본 브랜치 이름을 `main`으로 맞춥니다. (배포 설정이 `main`을 기준으로 합니다.)

```
git remote add origin https://github.com/<내 GitHub 계정>/moodtune.git
```
- **하는 일:** 내 컴퓨터의 폴더와 GitHub 저장소를 연결합니다. `<내 GitHub 계정>`을 실제 계정으로 바꾸세요.
- **실패:** `error: remote origin already exists.`가 나오면 이미 연결된 것이니 이 줄은 건너뛰세요.

```
git push -u origin main
```
- **하는 일:** 파일을 GitHub로 올립니다.
- **성공:** `Branch 'main' set up to track remote branch 'main' from 'origin'.`
- 처음에는 GitHub 로그인 창이 뜹니다. 안내에 따라 로그인하세요.
- **실패:** `Authentication failed` 또는 `Permission denied`는 로그인 정보 문제입니다. `rejected ... fetch first`는 1단계에서 README 등을 추가해 만든 저장소라서 생기며, 저장소를 지우고 빈 상태로 다시 만드는 것이 가장 쉽습니다.

### 3) Pages 켜기

1. GitHub 저장소 → **Settings** → 왼쪽 **Pages**.
2. **Build and deployment → Source**를 **GitHub Actions**로 바꿉니다.
3. 저장소의 **Actions** 탭에서 `GitHub Pages 배포` 실행이 초록색 체크가 되면 끝입니다. 처음에는 1~2분 걸립니다.
4. 주소는 `https://<계정>.github.io/moodtune/`입니다.
5. 이후 `main`에 올리는 변경은 자동으로 다시 배포됩니다.

### 4) 방법 B의 조건 (확인이 필요합니다)

Pages 주소는 HTTPS이고 Navidrome 서버와 **다른 출처**입니다. 그래서 두 가지가 필요합니다.

- **서버가 HTTPS여야 합니다.** `http://` 서버는 브라우저가 막습니다. 앱이 이 경우 안내 문구를 보여 줍니다. (`http://localhost`는 예외)
- **서버가 CORS를 허용해야 합니다.** Navidrome 공식 문서에서 CORS 설정은 확인하지 못했습니다. 허용하지 않는다면 서버 앞의 리버스 프록시(Nginx, Caddy 등)에서 `Access-Control-Allow-Origin` 헤더를 추가해야 할 수 있습니다. 연결이 `서버에 연결하지 못했어요 ... CORS 설정을 확인해 주세요`로 실패하면 이 부분을 의심하세요.

이 조건을 맞추기 어렵다면 방법 A를 쓰세요.

## 장르 → 기분 표 고치기

설정은 `js/engine.js`의 `GENRE_PROFILES`입니다.

```js
{ keys: ['jazz', '재즈'], v: 50, e: 25, moods: ['집중', '새벽감성', '비 오는 날'] },
```

- `keys`: 곡의 장르 이름에 들어 있는 단어. 영어는 단어 단위(`rock`은 `Post-Rock`에는 맞지만 `Rocket`에는 맞지 않음), 한글은 부분 일치로 찾습니다.
- `v`: 밝기 0(어두움) ~ 100(밝음). `e`: 에너지 0(잔잔) ~ 100(격렬).
- `moods`: 이 장르가 어울리는 기분.

곡 목록 아래에 `장르를 알 수 없는 곡이 많아요`가 보이면, 내 라이브러리의 장르 이름이 표에 없다는 뜻입니다. Navidrome 웹 화면의 장르 목록을 보고 표에 추가하세요.
곡에 BPM 값이 있으면 에너지에 일부 반영하지만, Navidrome이 BPM을 API로 주는지는 확인하지 못했습니다.

고친 뒤 확인: `node test/engine.test.js` → `엔진 테스트 통과`

## 추천이 만들어지는 과정

1. 선택한 기분(최대 3개)의 좌표를 평균 내고, 추천 방향(공감 / 기분 전환 / 진정)과 에너지 슬라이더로 목표 좌표를 옮깁니다.
2. 서버의 장르 목록(`getGenres`)에서 이 기분에 어울리는 장르를 최대 6개 고르고, 장르마다 곡 40개를 무작위로 가져옵니다(`getRandomSongs`). 장르와 상관없는 곡 60개도 함께 가져옵니다.
3. 곡마다 `점수 = w × 태그 일치 + (1 − w) × 거리 점수`를 계산합니다. `w`는 공감 0.55, 전환·진정 0.30입니다. 장르를 모르는 곡은 점수에 0.6을 곱해 뒤로 보냅니다. 같은 아티스트는 최대 2곡입니다.
4. 상위 6곡을 보여 주고, `다시 섞기`를 누르면 서버에서 곡을 새로 가져옵니다.

## 보안과 저장되는 정보

- **비밀번호는 저장하지 않습니다.** 로그인 순간에 Subsonic 표준 토큰(비밀번호와 임의 값을 섞은 MD5)을 만들어 이 브라우저에 저장합니다. 토큰만으로도 서버를 쓸 수 있으니 공용 컴퓨터에서는 `이 기기에 연결 정보 기억하기`를 끄고, 쓴 뒤 `연결 끊기`를 누르세요.
- 재생과 표지 주소에는 이 토큰이 들어갑니다. 주소를 다른 사람에게 공유하지 마세요.
- 프록시 서버는 `/navidrome/rest/` 요청만 전달하고, 화면 파일(`index.html`, `css/`, `js/`) 외에는 공개하지 않습니다. 로그에는 토큰이 담긴 주소 뒷부분을 남기지 않습니다.
- 기분 기록은 이 브라우저(`localStorage`)에만 저장되고 서버로 보내지 않습니다.
- 곡은 본인이 합법적으로 가진 파일만 서버에 올려 쓰세요. 이 앱은 남에게 음원을 배포하는 용도가 아닙니다.

## 검증 상태

모의 Navidrome 서버로 다음을 확인했습니다: 연결과 틀린 비밀번호 처리, 기분별 추천, 재생(소리 데이터 수신, 구간 요청 포함), 즐겨찾기, 새로고침 후 연결 복원, 프록시 경유 호출.

**실제 Navidrome 서버로는 아직 시험하지 못했습니다.** 처음 연결할 때 확인해 볼 것은 다음과 같습니다.

- 토큰 로그인이 되는지 (Subsonic 표준 방식이며, 읽어 본 문서 페이지에는 설명이 없었습니다)
- `getRandomSongs`의 `genre` 조건이 동작하는지
- 곡의 장르가 응답에 담겨 오는지
- FLAC 등을 브라우저가 못 재생하면 설정의 `mp3로 변환해서 재생`을 켜기 (서버에 ffmpeg가 있어야 합니다)

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `아이디나 비밀번호가 맞지 않아요.` | 사용자 이름과 비밀번호를 확인하세요. 대소문자를 구분합니다. |
| `서버에 연결하지 못했어요 ...` | 주소 오타, 서버 꺼짐, HTTPS/CORS 문제입니다. 방법 A(프록시)로 먼저 시험해 보세요. |
| `Subsonic 응답이 아니에요` | 주소가 Navidrome이 아닌 다른 서비스를 가리킵니다. 서버 주소만 넣으세요(`/app` 등 뒷부분 제외). |
| 곡이 나오지만 소리가 안 남 | 설정에서 `mp3로 변환해서 재생`을 켜 보세요. |
| 추천 곡이 매번 비슷하거나 엉뚱함 | 곡 목록 아래 안내를 확인하고 `GENRE_PROFILES`를 내 장르에 맞게 고치세요. |
| 곡이 하나도 안 나옴 | Navidrome에서 라이브러리 스캔이 끝났는지, 해당 계정이 라이브러리에 접근할 수 있는지 확인하세요. |
