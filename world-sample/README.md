# 무드튠 세계 음악 표본 수집 (1단계)

세계 각국의 전통음악과 로컬 인디 음악으로 기분별 추천 목록을 만들기 위한 첫 단계입니다.
[MusicBrainz](https://musicbrainz.org)(공개 음악 데이터베이스)에서 **지역 10곳, 지역당 아티스트 100명**을 받아서 두 가지를 확인합니다.

1. **AI 음악 차단:** 사람 활동 근거로 걸러 냈을 때 쓸 만한 아티스트가 얼마나 남는가
2. **기분 대응:** 남은 아티스트의 태그가 기분으로 얼마나 연결되는가

이 결과로 이 방식으로 계속 갈지 정합니다. 곡(녹음) 수집은 2단계입니다.

> **현재 검증 상태:** 가짜 MusicBrainz 서버(`test/mock-mb.js`)로 전체 흐름, 재시도, 캐시, 오류 처리를 확인했습니다.
> **실제 MusicBrainz로는 아직 한 번도 실행하지 못했습니다.** 처음 실행할 때 나올 수 있는 문제는 아래 "처음 실행에서 확인할 것"에 적어 두었습니다.

---

## 준비

### 1) Node.js 확인

이 폴더에서 PowerShell을 엽니다. (압축을 푼 `moodtune-world-sample` 폴더를 탐색기로 열고, 위쪽 주소창을 클릭해 `powershell`을 입력한 뒤 Enter)

```
node --version
```

- **하는 일:** 설치된 Node.js 버전을 보여 줍니다.
- **성공:** `v24.21.0`처럼 `v18` 이상의 숫자가 나옵니다.
- **실패:** `'node'은(는) 내부 또는 외부 명령...`이면 설치가 안 된 것입니다. https://nodejs.org 에서 LTS를 설치한 뒤 PowerShell을 껐다 다시 여세요.

패키지 설치(`npm install`)는 필요 없습니다.

### 2) 연락처 설정

```
$env:MB_CONTACT="내이메일@example.com"
```

- **하는 일:** 이 PowerShell 창에서만 쓰는 설정값 `MB_CONTACT`에 연락처를 넣습니다. 창을 닫으면 사라지고 파일에는 저장되지 않습니다.
- **왜 필요한가:** MusicBrainz는 요청마다 연락할 수 있는 정보가 담긴 User-Agent를 요구합니다. 이 값은 MusicBrainz로 가는 요청 머리글에만 들어가고, 문제가 생기면 그쪽에서 연락하는 용도입니다. 연락처가 없는 요청은 "익명"으로 분류돼 제한을 받습니다.
- **성공:** 아무 메시지가 없습니다.
- 이메일 대신 `https://`로 시작하는 웹 주소를 넣어도 됩니다. `@`나 `http`가 없는 값은 도구가 거부합니다.

## 실행

### 3) 작게 시험 (약 15초)

```
node collect.js --only MN --per-region 10
```

- **하는 일:** 몽골(MN) 한 곳에서 아티스트 10명만 받아서 판정하고 보고서를 만듭니다. 요청은 약 12회이고, MusicBrainz 규칙에 맞춰 요청 사이에 1.1초씩 쉽니다.
- **성공:** 아래처럼 나옵니다.
  ```
  무드튠 표본 수집을 시작합니다.
    지역 1곳 x 지역당 10명, 예상 요청 약 13회 (약 1분, 이미 받은 것은 건너뜀)
    서버: https://musicbrainz.org
  [MN 몽골] 후보 10명
    10/10 조회 완료
  완료했습니다. (네트워크 요청 11회, 캐시 사용 0회)
    수집 10명 → 통과 ... / 검수 ... / 제외 ...
    기분 대응률(통과+검수 중): ...%
  ```
- 보고서 열기:
  ```
  start out\report.html
  ```
  기본 브라우저에서 보고서가 열립니다. (`start`는 Windows에서 파일을 연결된 프로그램으로 여는 명령입니다.)

시험에서 오류가 나면 전체 실행으로 넘어가지 말고 아래 "오류 메시지"를 확인하세요.

### 4) 전체 실행 (약 20분)

```
node collect.js
```

- **하는 일:** 지역 10곳에서 각각 아티스트 100명을 받습니다. 요청은 약 1,030회이고 요청 사이에 1.1초씩 쉬어서 약 20분 걸립니다. 진행 상황이 20명마다 한 줄씩 나옵니다.
- **창은 닫지 말고 컴퓨터가 절전에 들어가지 않게 해 주세요.**
- **중간에 멈춰도 괜찮습니다.** `Ctrl + C`로 멈추거나 오류로 끊겨도 같은 명령을 다시 실행하면, 이미 받은 것은 `out\cache`에서 읽고 이어서 진행합니다.
- 요청 간격(`MB_DELAY_MS`)은 1000 밑으로 내려가지 않게 막아 두었습니다. MusicBrainz는 초당 1회를 넘기면 요청을 전부 거부합니다.

### 5) 결과 파일 (`out` 폴더)

| 파일 | 내용 |
|---|---|
| `report.html` | 보고서. 지역별 통과·검수·제외 수, 사유 상위, 기분에 대응되지 않은 태그, 검수 목록(검색과 필터 포함) |
| `artists.csv` | 전체 결과. 엑셀에서 한글이 깨지지 않게 저장됩니다. |
| `review.csv` | 사람이 확인할 검수·제외 목록 |
| `artists.json` | 프로그램용 전체 결과 |
| `cache` 폴더 | 받아 둔 응답. 지우면 다시 받습니다. |

## AI 음악 차단 방식 (날짜 기준 없음)

날짜로 자르지 않고, 아티스트가 **실제 사람으로 활동했다는 근거**를 점수로 셉니다. 근거가 약하면 통과시키지 않습니다.

**1) 바로 제외**
- 설명, 주석, 별칭, 태그에 "AI-generated", "artificial intelligence", "Suno", "Udio", `ai` 태그 등이 있음
- `config/blocklist.json`에 있는 아티스트
- 다른 근거가 아무리 많아도 이 두 경우는 제외입니다.

**2) 사람 활동 근거 점수** (`config/filter.json`에서 조정)

| 구분 | 근거 | 점수 |
|---|---|---|
| 강한 근거 | 위키데이터 또는 위키백과 문서 | 3 |
| 강한 근거 | ISNI/IPI 식별번호 | 2 |
| 강한 근거 | VIAF 등록 | 2 |
| 강한 근거 | 다른 아티스트와의 멤버·협업 관계 2건 이상 | 2 |
| 약한 근거 | 공식 홈페이지, Bandcamp, 평점 투표, 태그 투표 3 이상, 발매 3건 이상, 활동 시작 기록 | 각 1 |

**3) 판정**

| 판정 | 조건 |
|---|---|
| 통과 | 강한 근거가 있고, 점수 3 이상이고, 의심 패턴이 없음 |
| 검수 | 강한 근거는 있으나 점수가 모자람 / 의심 패턴(31일 안에 발매 8건 이상)이 있음 / 강한 근거 없이 약한 근거가 4점 이상 |
| 제외 | 그 밖의 모두 |

약한 근거(홈페이지, Bandcamp)는 AI 계정도 만들 수 있어서, 약한 근거만으로는 통과시키지 않습니다. 대신 이 때문에 위키나 식별번호가 없는 실제 소규모 인디가 검수·제외로 밀릴 수 있습니다. 표본 결과에서 이 비율을 보고 기준을 조정합니다.

**한계:** 어떤 데이터에도 "이 곡은 AI가 만들었다"는 확정 표시가 없으므로 100% 보장은 불가능합니다. 통과 아티스트도 곡을 목록에 넣기 전에 사람이 한 번 확인하세요. 곡 단위 근거(CD·LP·카세트 발매, 레이블, 공연 기록)는 2단계에서 추가합니다.

### 검수 결과를 반영하는 법

1. `report.html`의 검수 목록에서 아티스트 이름을 누르면 MusicBrainz 문서가 열립니다. 실제 활동을 확인하세요.
2. 허용할 아티스트의 MusicBrainz ID(문서 주소 끝의 긴 문자열)를 `config/approved.json`의 `mbids`에 넣습니다.
3. 제외할 아티스트는 `config/blocklist.json`에 넣습니다. 차단이 승인보다 우선합니다.
4. 다시 계산합니다. 받은 캐시를 쓰므로 몇 초면 끝납니다.
   ```
   node collect.js --offline
   ```
   - **성공:** `완료했습니다. (네트워크 요청 0회, 캐시 사용 1010회)` 처럼 나오고 `out` 파일이 갱신됩니다.
   - `--offline`은 이전 실행과 **같은 환경**에서만 캐시를 찾습니다. 캐시가 없으면 오류로 끝나고 기존 결과 파일은 지워지지 않습니다.

## 기분 대응 고치기

`config/moods.json`이 태그를 기분으로 바꾸는 사전입니다. 기분은 전통음악의 쓰임새에 가깝게 8개로 잡았습니다: 고요·명상, 그리움, 흥·축제, 위로·재우기, 먼 길·여행, 슬픔·애도, 일·리듬, 숲·자연.
사전은 제 판단으로 만든 초안입니다. 보고서의 "기분에 대응되지 않은 태그 상위"를 보며 연결할 만한 태그를 추가하고 `node collect.js --offline`으로 다시 계산하세요.

```json
"lullaby": [["위로·재우기", 1]],
"throat singing": [["숲·자연", 0.5], ["고요·명상", 0.5]]
```
값 `1`은 강한 연결, `0.5`는 약한 연결입니다.

## 지역 바꾸기

`config/regions.json`에서 국가 코드(ISO 2글자), 이름, 그 지역 전통음악을 찾는 태그를 고칩니다. 기본 10곳은 몽골, 말리, 인도, 튀르키예, 페루, 조지아, 인도네시아, 아일랜드, 에티오피아, 한국입니다.

## 처음 실행에서 확인할 것

실제 서버에서 아직 확인하지 못한 가정입니다. 시험 실행(3단계)에서 문제가 생기면 이 부분을 의심하세요.

- 검색 문법(`country:MN AND (tag:folk OR ...)`)이 기대대로 동작하는지. 결과가 0명이면 `[MN 몽골] 후보 0명`으로 나옵니다.
- 아티스트 조회에 붙이는 `inc` 조합이 허용되는지. 안 되면 `HTTP 400 ...` 오류가 납니다.
- 응답의 필드 이름(`release-groups`, `isnis`, `relations` 등)이 예상과 같은지. 다르면 근거 점수가 전부 0으로 나와서 제외가 대부분이 됩니다. 시험 실행 결과가 전부 "제외"로 나오면 이 경우입니다.

## 오류 메시지

| 메시지 | 뜻과 해결 |
|---|---|
| `[오류] MB_CONTACT 환경 변수가 필요합니다.` | 2단계를 하지 않았습니다. 같은 창에서 연락처를 먼저 설정하세요. |
| `[오류] MB_CONTACT는 이메일 주소(@ 포함) ...` | 연락처 형식이 틀렸습니다. |
| `[오류] 알 수 없는 옵션: ...` | 옵션 철자를 확인하세요. `node collect.js --help` |
| `네트워크 오류: ...` 후 재시도 | 인터넷 연결 문제입니다. 자동으로 최대 5번 재시도하고, 계속 실패하면 멈춥니다. 연결을 확인하고 같은 명령을 다시 실행하세요. |
| `MusicBrainz가 요청을 제한했습니다 (HTTP 503)` | 속도 제한입니다. 자동으로 기다렸다 재시도합니다. 계속되면 몇 분 뒤에 다시 실행하세요. |
| `HTTP 403 ...` | 차단됐거나 User-Agent가 거부됐습니다. 즉시 멈춥니다. 연락처 값을 확인하고 한참 뒤에 다시 하세요. |
| `HTTP 400 ...` | 요청 형식 문제입니다. 오류 문장 전체를 알려 주세요. |
| `[중단] ...` | 어떤 이유로든 중간에 끊겼습니다. 같은 명령을 다시 실행하면 이어집니다. |

## 가짜 서버로 시험해 보기 (선택)

실제 서버 없이 도구가 돌아가는지만 볼 때 씁니다. 데이터는 전부 가짜입니다.

PowerShell 창 **하나**에서:
```
node test/mock-mb.js
```
- **성공:** `모의 MusicBrainz 실행 중: http://127.0.0.1:5055` (창은 켜 둡니다.)

**새 창**에서 이 폴더로 이동해:
```
$env:MB_BASE_URL="http://127.0.0.1:5055"
$env:MB_CONTACT="test@example.com"
$env:MB_DELAY_MS="0"
node collect.js
```
- 몇 초 만에 끝나고 보고서 위에 "시험용 모의 데이터" 안내가 표시됩니다.
- 테스트: `node test/filter.test.js` → `필터·기분 변환 테스트 통과`
